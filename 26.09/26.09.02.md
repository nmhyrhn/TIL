# 1차 추가 구현 범위

## 포함 기능

1. **제공자 지정 대여 불가일**
    - 장비별 대여 불가 기간 등록·조회·삭제
    - 장비 상세 예약 가능 여부와 최종 예약 신청 검증에 반영
2. **후기·평점**
    - 완료 거래의 대여자만 후기 작성
    - 평균 평점·후기 수·후기 목록 제공
    - 작성자 본인의 후기 수정·삭제
3. **대여 많은 순 정렬**
    - COMPLETED 예약 건수 기준 정렬
    - 목록·상세에 완료 대여 횟수와 후기 요약 표시

## 선정 이유

- 기존 예약 흐름을 버리지 않고 자연스럽게 확장할 수 있다.
- 결제·SMTP·본인인증 같은 외부 서비스가 없어도 완성할 수 있다.
- 날짜 충돌, 권한, 관계형 데이터, 집계 쿼리를 모두 보여줄 수 있어 포트폴리오 가치가 높다.
- 세 기능이 서로 연결된다. 대여 불가일로 예약 정확도를 높이고, 완료 거래가 후기와 인기 순위로 축적된다.

## 이번 범위 제외

- 이메일 인증·비밀번호 재설정·회원 탈퇴·본인인증
- 역할 분리와 제공자 심사
- 장비 다중 이미지·수량 재고·대여 전후 사진
- 결제·에스크로·정산·수수료·쿠폰·광고
- 연체료·파손·분쟁·신고·관리자 화면
- 배송·알림·채팅

# 정책 정의

## 제공자 지정 대여 불가일

- 장비 소유자만 본인 장비의 기간을 관리한다.
- 시작일과 종료일을 모두 포함한다.
- 시작일은 종료일보다 늦을 수 없다.
- 종료일이 오늘보다 이전인 기간은 등록할 수 없다.
- ACTIVE·PAUSED 장비 모두 관리할 수 있다.
- 같은 장비의 대여 불가 기간끼리는 겹칠 수 없다.
- PENDING·CONFIRMED·RECEIPT_REQUESTED·RENTING·RETURNING 예약과 겹치면 등록할 수 없다.
- 기존 예약을 불가일 등록으로 취소하거나 변경하지 않는다.
- 사유는 선택이며 100자 이내다.
- 사유는 장비 소유자에게만 공개한다.
- 삭제하면 해당 날짜는 즉시 예약 가능 여부에 다시 포함한다.
- 공개 availability 응답은 예약과 직접 지정 기간을 합쳐 반환하며 사유와 종류는 숨긴다.
- 최종 예약 신청은 화면 결과를 신뢰하지 않고 트랜잭션 안에서 다시 검사한다.
- 예약 신청과 불가일 등록이 동시에 들어오면 동일 equipment 행을 잠그고 먼저 처리된 요청만 성공시킨다.

기간 충돌 조건:

```sql
existing.start_date <= requested.end_date
AND existing.end_date >= requested.start_date
```

## 후기·평점

- COMPLETED 예약만 후기 작성이 가능하다.
- 해당 예약의 renter만 작성할 수 있다.
- 예약 하나당 후기 하나만 허용한다.
- 평점은 1~5 정수이며 필수다.
- 내용은 선택이며 500자 이내다.
- 제공자와 제3자는 작성할 수 없다.
- 작성자는 본인 후기만 수정·삭제할 수 있다.
- 삭제된 후기는 평균과 후기 수에서 즉시 제외한다.
- 작성자 닉네임·평점·내용·작성일·수정 여부를 공개한다.
- 연락처와 이메일은 공개하지 않는다.
- 장비가 PAUSED여도 기존 후기는 유지한다.
- 예약 당시 스냅샷은 변경하지 않고 후기는 예약의 equipment_id에 연결한다.
- 신고·블라인드·관리자 삭제는 후속 범위로 둔다.

```
평균 평점 = ROUND(AVG(rating), 1)
후기 수 = COUNT(review.id)
후기 없음 = averageRating null, reviewCount 0
```

## 대여 많은 순

- 대여 횟수는 장비별 COMPLETED 예약 수다.
- 진행·취소·거절·만료 예약은 제외한다.
- 정렬 코드는 RENTAL_COUNT_DESC다.
- 횟수가 같으면 created_at 최신순이다.
- 기존 LATEST·PRICE_ASC·PRICE_DESC를 유지한다.
- ACTIVE 장비만 공개 목록에 표시한다.
- 초기에는 실시간 집계하며 equipment에 중복 카운트 컬럼을 추가하지 않는다.
- 성능 문제가 측정될 때만 집계 컬럼 또는 통계 테이블을 도입한다.

# 핵심 워크플로

## 대여 불가일

1. 제공자가 내 장비에서 대여 불가일 관리를 선택한다.
2. 기존 예약 차단일과 직접 지정한 날짜를 확인한다.
3. 시작일·종료일·사유를 입력한다.
4. 서버가 소유권을 확인하고 equipment 행을 잠근다.
5. 차단 예약 및 기존 불가 기간과 중복을 검사한다.
6. 충돌이 없으면 저장하고 availability에 즉시 반영한다.

## 후기

1. 대여자가 COMPLETED 거래를 조회한다.
2. 후기 미작성 상태에 후기 작성 버튼을 표시한다.
3. 평점과 내용을 입력한다.
4. 서버가 renter·COMPLETED·중복 여부를 검사한다.
5. 저장 후 예약 상세와 장비 상세의 통계를 갱신한다.

## 대여 많은 순

1. 사용자가 장비 목록에서 대여 많은 순을 선택한다.
2. 서버가 장비별 COMPLETED 예약 수를 집계한다.
3. 완료 건수 내림차순, 최신 등록순으로 반환한다.
4. 카드에 완료 횟수·평점·후기 수를 표시한다.

# 화면 기획

## 1. 장비 목록

추가 요소:

- 정렬 옵션에 **대여 많은 순**
- 카드에 **대여 완료 N회**
- 평균 평점과 후기 수
- 후기가 없으면 **아직 후기가 없습니다**

## 2. 장비 상세

추가 요소:

- 장비명 하단에 평균 평점·후기 수·대여 완료 횟수
- 하단 후기 목록
- 작성자 닉네임·별점·내용·작성일·수정됨 표시
- 최신 작성순, 10개 페이지 조회
- 비로그인 사용자도 조회 가능
- 후기 0건 빈 상태 표시

## 3. 내 장비 목록

- 각 장비에 **대여 불가일 관리** 버튼 추가
- 선택하면 해당 장비의 관리 화면으로 이동

## 4. 대여 불가일 관리

접근: 장비 소유자

표시:

- 장비명·대표 사진·상태
- 월 달력
- 기존 예약 차단 날짜
- 직접 지정한 불가 날짜
- 등록 목록과 사유

입력:

- 시작일 필수
- 종료일 필수
- 사유 선택, 100자

버튼:

- 기간 등록
- 직접 등록 기간 삭제
- 내 장비로 돌아가기

표현:

- 예약 차단일은 회색이며 삭제 불가
- 직접 지정일은 주황색이며 삭제 가능
- 과거 날짜 선택 불가

오류:

- 시작일과 종료일을 확인해주세요.
- 기존 예약과 겹치는 기간입니다.
- 이미 등록된 대여 불가 기간과 겹칩니다.
- 본인의 장비만 관리할 수 있습니다.

## 5. 후기 작성·수정

접근: COMPLETED 예약의 대여자

표시:

- 예약 당시 장비명·대표 사진
- 대여 기간·제공자 닉네임

입력:

- 평점 1~5 필수
- 내용 선택, 500자
- 글자 수

상태:

- 후기 없음: 작성 버튼
- 후기 있음: 수정·삭제
- COMPLETED 아님: 버튼 숨김
- 권한 없음: 403

# ERD 변경

## 관계

```
users
  ├─< equipment
  ├─< reservations
  └─< reviews

equipment
  ├─< reservations
  ├─< equipment_unavailable_periods
  └─< reviews

reservations
  └─ 0..1 reviews
```

## equipment_unavailable_periods

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| id | BIGINT | N | PK |
| equipment_id | BIGINT | N | equipment.id FK |
| start_date | DATE | N | 시작일 |
| end_date | DATE | N | 종료일 |
| reason | VARCHAR(100) | Y | 소유자용 사유 |
| created_at | DATETIME | N | 한국 시간 생성 시각 |

```sql
CHECK (start_date <= end_date)
INDEX idx_unavailable_equipment_dates
  (equipment_id, start_date, end_date)
```

날짜 범위 중복은 UNIQUE로 막을 수 없으므로 장비 행 잠금 트랜잭션에서 검사한다.

## reviews

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| id | BIGINT | N | PK |
| reservation_id | BIGINT | N | reservations.id FK, UNIQUE |
| equipment_id | BIGINT | N | equipment.id FK |
| reviewer_id | BIGINT | N | users.id FK |
| rating | TINYINT | N | 1~5 |
| content | VARCHAR(500) | Y | 후기 내용 |
| created_at | DATETIME | N | 생성 시각 |
| updated_at | DATETIME | N | 수정 시각 |

```sql
UNIQUE reviews(reservation_id)
CHECK (rating BETWEEN 1 AND 5)
INDEX idx_reviews_equipment_created
  (equipment_id, created_at)
INDEX idx_reviews_reviewer
  (reviewer_id, created_at)
```

기존 users·equipment·reservations 테이블에는 컬럼을 추가하지 않는다.

# API 명세

## 장비 목록 확장

```
GET /api/equipment?sort=RENTAL_COUNT_DESC&page=0&size=12
```

허용 sort:

```
LATEST
PRICE_ASC
PRICE_DESC
RENTAL_COUNT_DESC
```

응답 추가:

```json
{
  "completedRentalCount": 12,
  "averageRating": 4.8,
  "reviewCount": 9
}
```

## 장비 상세 확장

```
GET /api/equipment/{equipmentId}
```

응답에 completedRentalCount·averageRating·reviewCount를 추가한다.

## 공개 예약 불가 기간

```
GET /api/equipment/{equipmentId}/availability?from=2026-09-01&to=2026-10-31
```

```json
{
  "unavailableRanges": [
    {
      "startDate": "2026-09-10",
      "endDate": "2026-09-12"
    }
  ]
}
```

예약과 직접 지정 불가 기간을 합치고 사유·종류는 공개하지 않는다.

## 소유자 불가 기간 조회

```
GET /api/equipment/{equipmentId}/unavailable-periods
```

```json
{
  "items": [
    {
      "id": 20,
      "startDate": "2026-09-20",
      "endDate": "2026-09-22",
      "reason": "장비 점검"
    }
  ]
}
```

## 불가 기간 등록

```
POST /api/equipment/{equipmentId}/unavailable-periods
Content-Type: application/json
```

```json
{
  "startDate": "2026-09-20",
  "endDate": "2026-09-22",
  "reason": "장비 점검"
}
```

성공: 201, id 반환

오류 코드:

```
EQUIPMENT_NOT_OWNER
INVALID_DATE_RANGE
PAST_DATE
RESERVATION_DATE_CONFLICT
UNAVAILABLE_PERIOD_CONFLICT
```

## 불가 기간 삭제

```
DELETE /api/equipment/{equipmentId}/unavailable-periods/{periodId}
```

소유자와 소속 장비를 확인하고 204를 반환한다.

## 장비 후기 목록

```
GET /api/equipment/{equipmentId}/reviews?page=0&size=10
```

```json
{
  "items": [
    {
      "id": 30,
      "rating": 5,
      "content": "상태가 좋고 설명과 같았습니다.",
      "reviewerNickname": "렌즈빌려요",
      "createdAt": "2026-09-15T20:10:00+09:00",
      "updated": false
    }
  ],
  "page": 0,
  "size": 10,
  "totalElements": 1,
  "totalPages": 1
}
```

## 후기 작성

```
POST /api/reservations/{reservationId}/review
Content-Type: application/json
```

```json
{
  "rating": 5,
  "content": "상태가 좋고 설명과 같았습니다."
}
```

검사 순서:

1. 로그인 사용자와 예약 존재 확인
2. 현재 사용자가 renter인지 확인
3. COMPLETED 상태 확인
4. 중복 후기 확인
5. 평점·글자 수 검증
6. equipment_id와 reviewer_id를 서버 값으로 저장

오류:

```
NOT_RESERVATION_RENTER
RESERVATION_NOT_COMPLETED
REVIEW_ALREADY_EXISTS
INVALID_RATING
```

## 후기 수정·삭제

```
PATCH /api/reviews/{reviewId}
DELETE /api/reviews/{reviewId}
```

수정 요청은 rating과 content를 포함한다. 작성자만 가능하며 삭제 성공은 204다.

## 예약 상세 확장

후기 미작성 완료 예약의 대여자:

```json
{
  "review": null,
  "actions": ["CREATE_REVIEW"]
}
```

후기 작성 후:

```json
{
  "review": {
    "id": 30,
    "rating": 5,
    "content": "상태가 좋고 설명과 같았습니다."
  },
  "actions": ["EDIT_REVIEW", "DELETE_REVIEW"]
}
```

## 완료 정의

- 제공자가 지정한 불가 기간이 상세 조회와 최종 예약 검증에 반영된다.
- 완료 거래의 대여자가 후기 하나를 작성·수정·삭제할 수 있다.
- 장비 상세에서 평균 평점과 후기 목록을 볼 수 있다.
- 장비 목록을 완료 대여 횟수로 정렬할 수 있다.
- 모든 권한·상태·충돌 검증을 서버에서 수행한다.
- 기존 MVP 거래 흐름이 회귀 없이 동작한다.
- 백엔드 테스트와 프론트 빌드가 통과한다.

# 위험과 후속 결정

- 실시간 집계가 느려질 때 측정 결과를 근거로 통계 컬럼 또는 집계 테이블을 추가한다.
- 외부 공개 전 후기 신고·블라인드·관리자 처리 정책이 필요하다.
- 반복 불가일과 요일 설정은 사용 요구가 확인된 뒤 확장한다.
- 수량 재고가 추가되면 현재 장비 단위 날짜 차단 모델을 다시 설계해야 한다.
- 제공자 평가를 장비 평점과 분리할지는 후기 사용성을 확인한 뒤 결정한다.
