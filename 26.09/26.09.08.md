# 1. Orchestrator는 무엇인가
UiPath Studio가 “로봇 프로그램을 만드는 개발 도구”라면, Orchestrator는 그 로봇을 운영하는 관리 서버입니다.
UiPath Studio
  └─ 자동화 개발·테스트·배포

UiPath Orchestrator
  ├─ 로봇 실행
  ├─ 일정 예약
  ├─ 설정·계정 보관
  ├─ 처리할 업무 배분
  └─ 로그·성공·실패 확인
Asset
Asset은 Orchestrator에 저장하는 공용 설정값입니다.
예:
- 업무 시스템 URL
- 다운로드 폴더 경로
- 담당자 이메일
- 재시도 횟수
- 지역 코드
- 실행 환경 이름
Asset 이름: ERP_URL
값: https://erp.example.com

Asset 이름: RetryCount
값: 3
Studio에서는 Get Asset 등의 활동으로 값을 읽습니다.
왜 코드에 직접 입력하지 않을까요?
' 좋지 않은 방식
erpUrl = "https://erp.example.com"
URL이 변경되면 프로젝트를 수정하고 다시 배포해야 하기 때문입니다. Asset을 쓰면 Orchestrator에서 값만 변경하면 됩니다.
보통 다음처럼 나눕니다.
- 프로젝트 내부에서만 사용하는 값 → Config.xlsx
- 운영자가 자주 변경하는 공용 설정 → Orchestrator Asset
- 아이디·비밀번호 → Credential Asset
Credential Asset
Credential Asset은 로그인 정보를 보관하는 전용 Asset입니다.
이름: ERP_Login
Username: rpa_robot01
Password: ********
Studio에서는 Get Credential 또는 해당 Credential 활동으로 읽습니다.
중요한 점:
- 비밀번호를 XAML이나 Config.xlsx에 직접 적지 않음
- 로그에 비밀번호를 출력하지 않음
- 필요한 Robot·폴더에만 권한 부여
- 운영 계정과 개발 계정을 분리
REFramework의 Init에서 Credential을 읽고 로그인하는 경우가 많습니다.
Init
  ├─ Config 읽기
  ├─ Credential Asset 읽기
  ├─ ERP 실행
  └─ 로그인

# 2. Queue와 Queue Item
Queue는 Robot이 처리할 업무 목록입니다.
예를 들어 주문 100건을 처리한다면:
Orders Queue
  ├─ 주문 001
  ├─ 주문 002
  ├─ 주문 003
  └─ ...
Queue 안의 업무 한 건이 Queue Item입니다.
Queue Item에 들어가는 정보
예를 들어 주문 한 건을 다음처럼 저장할 수 있습니다.
Reference: ORDER-2026-001
Specific Content:
  CustomerName = 홍길동
  ProductCode  = P100
  Quantity     = 3
- Reference: 해당 업무를 식별하는 값
- Specific Content: 실제 처리할 데이터
- Status: New, In Progress, Successful, Failed 등
- Priority: 우선순위
- Deadline: 처리 기한
REFramework에서의 Queue Item
Get Transaction Data
  └─ Queue에서 주문 한 건 가져오기

Process Transaction
  └─ 해당 주문을 ERP에 입력

Set Transaction Status
  ├─ 성공 → Successful
  └─ 실패 → Failed
한 건이 실패해도 나머지 주문은 계속 처리할 수 있습니다.
Dispatcher와 Performer
Dispatcher는 처리할 데이터를 Queue에 넣습니다.
Excel 주문 100건
       ↓
Dispatcher
       ↓
Orchestrator Queue 100건
Performer는 Queue에서 한 건씩 가져와 처리합니다.
Orchestrator Queue
       ↓
Performer Robot
       ↓
ERP 주문 등록
분리하는 이유는 여러 Robot이 같은 Queue를 나누어 처리할 수 있기 때문입니다.
