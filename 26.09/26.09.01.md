# 문서 목적

확정된 ERD와 화면 행동을 Spring Boot REST API로 정의한다.

- MVP 정책 기획서
- MVP 화면 정의서
- ERD·데이터 정의서

> 현재 문서는 검토용 전체 초안이다. 검토 후 필드명과 응답 범위를 확정한다.
> 

# API 설계 원칙

- Spring Boot REST API
- JSON 요청·응답
- 인증은 Spring Security 세션 쿠키 사용
- 역할이 아닌 리소스 소유자와 예약 참여자 기준으로 권한 검사
- 예약 상태 변경과 기간 중복을 서버에서 검증
- 상태 변경은 범용 status 수정 API가 아닌 행동별 전용 API 제공
- 목록 API는 0부터 시작하는 페이지 번호 방식
- 클라이언트가 보낸 가격을 신뢰하지 않고 서버에서 계산
- 배포는 보류하고 React·Spring Boot·MySQL을 로컬에서 실행
- 서버·DB·API 업무 시간 기준은 Asia/Seoul로 통일

# 공통 규칙

## 기본 URL

```
/api
```

## 날짜와 시간

모든 업무 일시는 Asia/Seoul 한국 시간(+09:00)으로 생성·저장·조회한다.

```
날짜: YYYY-MM-DD
시간: HH:mm
일시: ISO 8601
```

예:

```
2026-09-01
14:30
2026-08-26T15:00:00+09:00
```

## 인증 방식

- 로그인 성공 시 Spring Security 세션 생성
- 세션 ID는 HttpOnly 쿠키로 전달
- 세션 유효시간 2시간
- 프론트엔드는 쿠키 포함 요청 사용
- 로그아웃 시 서버 세션 삭제
- 비밀번호는 BCrypt로 암호화
- JWT·리프레시 토큰 API는 사용하지 않음

## HTTP 상태 코드

| 상태 | 용도 |
| --- | --- |
| 200 | 조회·수정·상태 변경 성공 |
| 201 | 회원·장비·예약 생성 성공 |
| 204 | 삭제·로그아웃 성공 |
| 400 | 입력값·상태 전이 오류 |
| 401 | 로그인 필요 |
| 403 | 접근 권한 없음 |
| 404 | 리소스 없음 |
| 409 | 이메일·닉네임 중복, 예약 기간 충돌 |

# 예약 API

## 예약 신청

```
POST /api/reservations
Content-Type: application/json
```

요청:

```json
{
  "equipmentId": 10,
  "startDate": "2026-09-01",
  "endDate": "2026-09-03",
  "pickupTime": "14:00",
  "returnTime": "18:30",
  "note": "15분 전 연락 부탁드립니다."
}
```

서버 처리:

1. 로그인 사용자와 장비 소유자가 다른지 확인
2. ACTIVE 장비인지 확인
3. 날짜·시간 형식 검증
4. equipment 행 잠금
5. 차단 상태 예약의 기간 중복 조회
6. 장비·역·가격 스냅샷 생성
7. 대여료와 결제 금액 계산
8. 현재 시각 + 24시간을 expiresAt으로 저장
9. PENDING 예약 생성

응답: 201 Created

```json
{
  "id": 100,
  "status": "PENDING",
  "expiresAt": "2026-08-27T15:00:00+09:00"
}
```

# 예약 대기 만료

- PENDING 생성 시 한국 시간 기준 expiresAt 저장
- Spring `@Scheduled` 작업이 1분마다 만료 대상을 조회
- expiresAt이 지난 PENDING을 EXPIRED로 변경
- 승인 API는 스케줄 실행 여부와 관계없이 expiresAt을 다시 검사해 만료 시각 이후 승인을 차단
- 예약 조회·신규 예약 중복 검사도 만료된 PENDING을 차단 상태로 취급하지 않음
- EXPIRED 예약은 날짜를 차단하지 않음
- Quartz·메시지 큐 등 별도 스케줄링 도구는 사용하지 않음

# 로컬 파일 제공

```
저장 폴더: ./uploads/equipment
접근 URL: /files/equipment/{UUID}.{확장자}
DB 저장값: /files/equipment/{UUID}.{확장자}
```

- 업로드 전 MIME 타입·확장자·5MB 크기 검증
- 클라이언트 원본 파일명을 저장 파일명으로 사용하지 않음
- 이미지 교체 시 새 파일 저장과 DB 수정이 성공한 뒤 이전 파일 삭제
- 예약 스냅샷이 참조하는 이미지는 유지
- 배포 시 로컬 저장을 S3 등 외부 저장소로 교체
