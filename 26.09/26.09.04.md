# 로컬 이미지 저장 정책

## 확정 구조

- **이미지 파일 자체는 DB에 저장하지 않는다.**
- 파일은 Spring Boot가 관리하는 로컬 `uploads/img` 폴더에 저장한다.
- DB에는 장비와 파일을 연결하기 위한 **상대 경로와 표시 순서만** 저장한다.
- 예: 파일 위치 `backend/uploads/img/equipment/{equipmentId}/{uuid}.jpg`
- 예: DB 값 `/files/img/equipment/{equipmentId}/{uuid}.jpg`
- React는 `http://localhost:8080`과 상대 경로를 결합해 이미지를 표시한다.
- 절대 경로는 DB에 저장하지 않는다.

<aside>
💡

파일 경로까지 전혀 DB에 저장하지 않고 폴더만 조회하는 방식은 대표 이미지·정렬·삭제·장비 연결을 파일명 규칙에 의존하게 된다. 따라서 파일 바이너리는 폴더에만 저장하고, 최소 메타데이터만 DB에 저장한다.

</aside>

## 파일 규칙

- 허용 형식: JPG, JPEG, PNG
- 파일당 최대 5MB
- 장비 게시물 사진 최소 1장, 최대 5장
- 서버가 UUID 파일명을 생성해 이름 충돌과 경로 조작을 방지한다.
- 업로드 파일의 원래 이름은 저장 경로에 사용하지 않는다.
- 장비 삭제 시 해당 장비 이미지 파일과 메타데이터를 삭제한다.
- 이미지 교체·삭제 실패 시 DB와 파일이 불일치하지 않도록 서비스 트랜잭션에서 처리한다.
- 로컬 개발용 `uploads/`는 Git에서 제외한다.

## 모바일 촬영·갤러리

- **사진 촬영** 버튼: `accept="image/*" capture="environment"`로 후면 카메라를 유도한다.
- **갤러리에서 선택** 버튼: `accept="image/jpeg,image/png" multiple`을 사용한다.
- 촬영 사진과 갤러리 선택 사진을 합쳐 최대 5장까지만 허용한다.
- 브라우저의 `capture` 지원 방식은 기기마다 다르므로 일반 파일 선택으로 전환될 수 있다.
- 선택 즉시 로컬 미리보기를 표시하고 아직 서버에 저장하지 않는다.
- 등록·수정 제출 시 한 번에 `multipart/form-data`로 전송한다.

# 반응형 정책

- 모바일 기준 너비: 360px 이상
- 태블릿 기준: 768px 이상
- 데스크톱 기준: 1024px 이상
- 모바일에서는 헤더 메뉴 버튼을 제공하고 주요 기능을 숨기지 않는다.
- 목록은 모바일 1열, 태블릿 2열, 데스크톱 가변 다열로 표시한다.
- 버튼과 체크박스 터치 영역은 최소 44px로 유지한다.
- 갤러리는 모바일에서 대표 이미지 1장과 가로 스크롤 썸네일로 표시한다.
- 폼은 모바일 1열, 넓은 화면 2열로 표시한다.
- 긴 장비명·역명·금액으로 가로 스크롤이 발생하지 않아야 한다.

# 기능 정책

## 다중 이미지·갤러리

- 최초 등록 시 1장 이상 필수, 최대 5장이다.
- 첫 번째 선택 이미지를 기본 대표 이미지로 지정한다.
- 등록 후 다른 이미지를 대표로 지정할 수 있다.
- 기존 이미지를 삭제할 수 있지만 최소 1장은 유지해야 한다.
- 대표 이미지를 삭제하면 표시 순서가 가장 빠른 이미지를 자동 대표로 지정한다.
- 기존 예약에는 예약 당시 대표 이미지 스냅샷을 유지한다.
- 3차에서는 이미지 순서 드래그를 제외하며 대표 지정만 제공한다.

## 수량별 재고

- 장비 등록자는 총수량을 1 이상 정수로 입력한다.
- 대여자는 예약 수량을 1 이상 선택한다.
- 날짜가 하루라도 겹치는 차단 상태 예약의 수량 합계를 재고에서 차감한다.
- 차단 상태: PENDING, CONFIRMED, RECEIPT_REQUESTED, RENTING, RETURNING
- 예약 가능 수량 = 총수량 − 겹치는 예약 수량 합계
- 예약 신청 시 조회 결과만 믿지 않고 서버 트랜잭션에서 다시 계산한다.
- 예약 당시 수량과 단가를 스냅샷으로 보존한다.
- 대여료 = 일일 대여료 × 대여 일수 × 예약 수량
- 결제 금액 = 대여료 + 보증금 × 예약 수량
- 기존 예약이 있는 장비는 총수량을 이미 점유된 최대 수량 아래로 줄일 수 없다.
- 같은 날짜 반납·재대여 금지 정책은 유지한다.

## 디지털 구성품 체크리스트

- 장비 제공자는 장비 등록·수정 시 구성품명을 최대 20개 등록한다.
- 구성품명은 항목당 50자 이내이며 빈 항목과 같은 장비 내 중복 이름을 허용하지 않는다.
- 수량별 구성품 개수 추적은 제외하고 확인 여부만 저장한다.
- 제공자는 대여 전 상태 기록에서 모든 구성품을 확인해야 수령 요청할 수 있다.
- 대여자는 현장에서 대여 전 체크 결과를 확인하고 수령 승인한다.
- 대여자는 반납 상태 기록에서 각 구성품의 반납 여부를 체크한다.
- 누락 항목이 있어도 반납 요청은 가능하지만 특이사항 입력을 필수로 한다.
- 체크 결과는 예약 당시 구성품명 스냅샷으로 저장해 이후 장비 수정의 영향을 받지 않는다.

## 반복 대여 불가일

- 장비별로 월요일부터 일요일까지 복수 요일을 지정할 수 있다.
- 해당 요일이 예약 기간에 하루라도 포함되면 신규 예약할 수 없다.
- 기존 특정 기간 대여 불가일과 함께 적용한다.
- 이미 확정된 예약에는 새 반복 불가일을 소급 적용하지 않는다.
- 반복 불가일 중복 등록은 허용하지 않는다.

# 워크플로

1. 제공자가 장비명·가격·보증금·총수량·구성품·이미지를 등록한다.
2. 필요하면 대표 이미지와 반복 대여 불가 요일을 설정한다.
3. 대여자가 날짜·시간·수량을 선택한다.
4. 서버가 특정 기간 불가일, 반복 요일, 겹치는 예약 수량을 검사한다.
5. 예약 당시 장비 정보·대표 이미지·구성품·수량·금액을 스냅샷으로 저장한다.
6. 제공자가 대여 전 사진과 구성품 체크 결과를 기록한다.
7. 수령·대여·반납 흐름은 기존 2차 상태 전환을 유지한다.
8. 대여자가 반납 사진과 구성품 체크 결과를 기록한다.

# API 명세

## 장비 등록

- `POST /api/equipment`
- `multipart/form-data`
- `data`: 장비 정보, totalQuantity, components
- `images`: JPG·PNG 1~5장
- 모바일 촬영 파일과 갤러리 파일을 같은 images 파트로 처리

## 장비 상세

- `GET /api/equipment/{equipmentId}`
- images, totalQuantity, components 포함
- images 항목: id, imageUrl, displayOrder, primary

## 이미지 추가

- `POST /api/equipment/{equipmentId}/images`
- images 1장 이상, 추가 후 전체 최대 5장
- 장비 소유자만 가능

## 대표 이미지 지정

- `PATCH /api/equipment/{equipmentId}/images/{imageId}/primary`
- 장비 소유자만 가능

## 이미지 삭제

- `DELETE /api/equipment/{equipmentId}/images/{imageId}`
- 최소 1장 유지
- DB 메타데이터와 로컬 파일을 함께 삭제

## 장비 수정

- `PATCH /api/equipment/{equipmentId}`
- totalQuantity와 components 수정
- 이미 점유된 수량보다 totalQuantity를 작게 변경하면 409

## 예약 가능 수량

- `GET /api/equipment/{equipmentId}/availability?from={date}&to={date}`
- 기존 reserved·unavailable와 함께 availableQuantity 반환
- 반복 불가 요일 포함 시 availableQuantity는 0

## 예약 신청

- `POST /api/reservations`
- 기존 요청에 quantity 추가
- 부족하면 409 INSUFFICIENT_STOCK
- 반복 불가 요일이면 409 RECURRING_UNAVAILABLE_DATE

## 반복 불가 요일 조회·저장

- `GET /api/equipment/{equipmentId}/unavailable-weekdays`
- `PUT /api/equipment/{equipmentId}/unavailable-weekdays`
- 요청: weekdays 배열

## 상태 기록 변경

- 대여 전·반납 상태 기록 multipart의 data 파트에 componentChecks 배열 추가
- 대여 전에는 모든 항목 checked=true 필수
- 반납 시 checked=false 항목이 있으면 conditionNote 필수
