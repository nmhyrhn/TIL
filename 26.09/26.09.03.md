# 2차 추가 구현 범위

## 포함

1. 대여 전 상태 사진과 특이사항 기록
2. 반납 상태 사진과 특이사항 기록
3. 상태 기록이 없을 때 예약 상태 전환 차단
4. 연체 중 표시
5. 예상·최종 연체 일수와 연체료 계산
6. 대여자 반납 요청 시각과 제공자 반납 완료 시각 분리 저장

## 제외

- 실제 연체료 결제와 자동 청구
- 보증금 자동 차감
- 파손 배상금 산정
- 분쟁 접수와 관리자 판정
- 사진 비교 AI
- 장비 게시물 다중 이미지

# 확정 정책

## 상태 사진

- 대여 전 사진은 **정확히 1장**이며 필수다.
- 반납 사진은 **정확히 1장**이며 필수다.
- JPG·PNG만 허용하고 파일당 최대 5MB로 기존 이미지 정책을 따른다.
- 구성품은 시스템 체크리스트를 만들지 않고 당사자가 현장에서 확인한다.
- 상태 특이사항은 선택 입력이며 최대 500자로 제한한다.
- 대여 전 기록 작성자는 장비 제공자다.
- 반납 기록 작성자는 대여자다.
- 다른 예약의 상태 기록을 재사용하지 않는다.

## 작성·수정 가능 시점

- 대여 전 기록은 예약이 CONFIRMED인 동안 작성·수정할 수 있다.
- 제공자가 수령 요청을 처리한 뒤에는 대여 전 기록을 수정할 수 없다.
- 반납 기록은 예약이 RENTING인 동안 작성·수정할 수 있다.
- 대여자가 반납 요청을 처리한 뒤에는 반납 기록을 수정할 수 없다.
- 여기서 “예약 전 수정”은 각 단계의 상태 전환 요청 전까지 수정 가능하다는 의미로 적용한다.
- 상태 기록은 삭제 기능 없이 사진과 내용을 교체하는 방식으로 수정한다.

## 상태 전환 제한

- 대여 전 상태 기록이 없으면 제공자는 수령 요청을 할 수 없다.
- 대여 전 상태 기록이 없으면 대여자는 수령 승인을 할 수 없다.
- 반납 상태 기록이 없으면 대여자는 반납 요청을 할 수 없다.
- 반납 상태 기록이 없으면 제공자는 반납 완료를 처리할 수 없다.
- 프론트에서 버튼을 숨기거나 비활성화하더라도 서버에서 반드시 다시 검증한다.

## 시각 구분

- **예약 반납 예정 시각:** 예약 종료일과 반납 시간을 결합한 한국 시간
- **반납 요청 시각(returnRequestedAt):** 대여자가 반납 요청 버튼을 누른 서버 시각
- **반납 완료 시각(completedAt):** 제공자가 사진과 상태를 확인하고 반납 완료 버튼을 누른 서버 시각
- 실제 거래 종료 기록은 completedAt을 사용한다.
- 연체료 계산 종료 시각은 returnRequestedAt을 사용한다.
- 따라서 제공자가 확인을 늦게 하더라도 추가 연체료가 발생하지 않는다.

## 연체 계산

- 예약 반납 예정 시각까지 대여자가 반납 요청을 하지 않으면 그 이후부터 연체로 본다.
- 반납 요청 전에는 현재 서버 시각을 기준으로 예상 연체 일수와 예상 연체료를 계산한다.
- 반납 요청 시 최종 연체 일수와 최종 연체료를 계산하여 저장한다.
- 24시간 단위가 아니라 초과 시간을 날짜 단위로 올림한다.
- 1분 또는 30분만 초과해도 1일 연체로 계산한다.
- 연체료 상한은 없다.
- 연체료는 자동 결제하지 않고 당사자가 현장에서 직접 정산한다.
- **초과 시간:** 계산 기준 시각 − 예약 반납 예정 시각
- **연체 일수:** 초과 시간이 0 이하이면 0, 양수이면 초과 분 ÷ 1,440을 올림
- **연체료:** 예약 당시 일일 대여료 × 연체 일수

예시:

| 반납 예정 | 대여자 반납 요청 | 제공자 완료 | 연체 |
| --- | --- | --- | --- |
| 9월 10일 18:00 | 9월 10일 17:50 | 9월 10일 20:00 | 0일 |
| 9월 10일 18:00 | 9월 10일 18:30 | 9월 10일 19:00 | 1일 |
| 9월 10일 18:00 | 9월 11일 18:30 | 9월 12일 10:00 | 2일 |

## 파손·누락

- 사진이나 특이사항에 파손·누락을 기록할 수 있다.
- 현재는 별도 분쟁 상태를 추가하지 않는다.
- 파손·누락이 있어도 제공자는 반납 완료 처리를 진행한다.
- 배상과 협의는 당사자가 개별 처리한다.

# 워크플로

1. 예약 확정(CONFIRMED)
2. 제공자가 대여 전 사진 1장과 특이사항 등록
3. 제공자가 수령 요청(RECEIPT_REQUESTED)
4. 대여자가 사진과 장비 상태 확인
5. 대여자가 수령 승인(RENTING)
6. 대여자가 반납 사진 1장과 특이사항 등록
7. 반납 예정 시각 초과 시 연체 중 표시
8. 대여자가 반납 요청(RETURNING), returnRequestedAt과 최종 연체 금액 저장
9. 제공자가 사진과 상태 확인
10. 제공자가 반납 완료(COMPLETED), completedAt 저장

# 화면 기획

## 대여 전 상태 등록

접근: CONFIRMED 예약의 제공자

- 예약 당시 장비명·대표 사진·대여 기간
- 사진 1장 필수 업로드
- 상태·기존 흠집 특이사항 입력
- 저장 및 사진 교체
- 기록 저장 후 수령 요청 버튼 활성화

## 대여 전 상태 확인

접근: RECEIPT_REQUESTED 예약의 대여자

- 제공자가 등록한 사진과 특이사항
- 현장 구성품 확인 안내
- 수령 승인 버튼

## 반납 상태 등록

접근: RENTING 예약의 대여자

- 대여 전 사진과 반납 사진 비교 표시
- 반납 사진 1장 필수 업로드
- 파손·누락·특이사항 입력
- 현재 예상 연체 일수와 예상 연체료
- 기록 저장 후 반납 요청 버튼 활성화

## 반납 상태 확인

접근: RETURNING 예약의 제공자

- 대여 전·반납 사진
- 대여자가 작성한 특이사항
- 반납 요청 시각
- 최종 연체 일수와 연체료
- 반납 완료 버튼

## 예약 목록·상세 공통

- 반납 예정 시각을 넘긴 RENTING 예약에 `연체 중` 표시
- 예상 연체 일수·금액 표시
- RETURNING·COMPLETED는 저장된 최종 연체 일수·금액 표시
- 제공자의 완료 처리가 늦어져도 금액이 증가하지 않음

# ERD 변경

## 관계

- reservations 1 : 0..2 rental_condition_records
- 한 예약에 PRE_RENTAL 1건과 RETURN 1건까지 저장
- users 1 : N rental_condition_records
- equipment와 상태 기록은 reservations를 통해 연결

## rental_condition_records

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| id | BIGINT | N | PK |
| reservation_id | BIGINT | N | reservations.id FK |
| writer_id | BIGINT | N | users.id FK |
| record_type | VARCHAR(20) | N | PRE_RENTAL 또는 RETURN |
| image_url | VARCHAR(500) | N | 상태 사진 1장 |
| condition_note | VARCHAR(500) | Y | 흠집·파손·누락 등 특이사항 |
| created_at | DATETIME | N | 한국 시간 생성 시각 |
| updated_at | DATETIME | N | 한국 시간 수정 시각 |

제약과 인덱스:

- UNIQUE(reservation_id, record_type)
- INDEX(reservation_id)
- INDEX(writer_id, created_at)
- record_type은 PRE_RENTAL, RETURN만 허용
- DB에는 URL만 저장하고 실제 파일은 기존 로컬 이미지 저장 폴더에 저장

## reservations 추가 컬럼

| 컬럼 | 타입 | NULL | 설명 |
| --- | --- | --- | --- |
| return_requested_at | DATETIME | Y | 대여자가 반납 요청한 한국 시각 |
| completed_at | DATETIME | Y | 제공자가 반납 완료한 한국 시각 |
| overdue_days | INT | N | 최종 연체 일수, 기본 0 |
| overdue_fee | BIGINT | N | 최종 연체료, 기본 0 |

예상 연체 값은 조회 시 계산하고 DB에 저장하지 않는다. 최종 값만 반납 요청 시 저장한다.

# API 명세

## 상태 기록 조회

- `GET /api/reservations/{reservationId}/condition-records`
- 예약 당사자만 조회 가능
- preRentalRecord와 returnRecord를 반환
- 각 기록은 id, recordType, imageUrl, conditionNote, writerId, createdAt, updatedAt 포함

## 대여 전 상태 등록

- `POST /api/reservations/{reservationId}/condition-records/pre-rental`
- Content-Type: multipart/form-data
- data 파트: conditionNote
- image 파트: JPG·PNG 1장, 최대 5MB
- CONFIRMED 예약의 제공자만 가능
- 성공 201

## 대여 전 상태 수정

- `PATCH /api/reservations/{reservationId}/condition-records/pre-rental`
- 사진은 선택이며 전달 시 기존 사진 교체
- 상태가 CONFIRMED일 때 제공자만 가능
- 수령 요청 이후 409 반환

## 반납 상태 등록

- `POST /api/reservations/{reservationId}/condition-records/return`
- Content-Type: multipart/form-data
- data 파트: conditionNote
- image 파트: JPG·PNG 1장, 최대 5MB
- RENTING 예약의 대여자만 가능
- 성공 201

## 반납 상태 수정

- `PATCH /api/reservations/{reservationId}/condition-records/return`
- 사진은 선택이며 전달 시 기존 사진 교체
- 상태가 RENTING일 때 대여자만 가능
- 반납 요청 이후 409 반환

## 수령 요청 기존 API 변경

- `POST /api/reservations/{reservationId}/receipt-request`
- 대여 전 기록이 없으면 409 PRE_RENTAL_RECORD_REQUIRED
- 성공 시 기존처럼 RECEIPT_REQUESTED로 변경

## 수령 승인 기존 API 변경

- `POST /api/reservations/{reservationId}/receipt-confirm`
- 대여 전 기록이 없으면 409 PRE_RENTAL_RECORD_REQUIRED
- 성공 시 RENTING으로 변경

## 반납 요청 기존 API 변경

- `POST /api/reservations/{reservationId}/return-request`
- 반납 기록이 없으면 409 RETURN_RECORD_REQUIRED
- 서버 시각을 returnRequestedAt으로 저장
- 예약 종료 일시와 비교하여 overdueDays·overdueFee 저장
- 성공 시 RETURNING으로 변경

## 반납 완료 기존 API 변경

- `POST /api/reservations/{reservationId}/return-complete`
- 반납 기록이 없으면 409 RETURN_RECORD_REQUIRED
- 서버 시각을 completedAt으로 저장
- overdueDays·overdueFee는 다시 계산하지 않음
- 성공 시 COMPLETED로 변경

## 예약 응답 추가 필드

- returnRequestedAt
- completedAt
- isOverdue
- overdueDays
- overdueFee
- hasPreRentalRecord
- hasReturnRecord

RENTING 상태에서는 overdueDays와 overdueFee를 현재 시각 기준 예상값으로 반환한다. RETURNING·COMPLETED 상태에서는 저장된 최종값을 반환한다.

# 완료 정의

- 예약 당사자가 단계별 상태 사진을 조회할 수 있다.
- 사진이 없으면 수령·반납 상태 전환이 불가능하다.
- 대여자는 반납 요청 시점까지만 연체료를 부담한다.
- 제공자의 반납 완료 지연은 연체료에 영향을 주지 않는다.
- 예상값과 최종 저장값이 구분된다.
- 외부 결제 없이 현장 정산용 금액만 제공한다.
- 모든 시간은 한국 시간 기준으로 처리한다.
