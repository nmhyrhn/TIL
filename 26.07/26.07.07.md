# TIL - 전체 QA 기반 오류 확인 및 수정

전체 QA 과정에서 발견된 오류와 미구현 항목을 확인하고, 필요한 수정 작업을 진행했다.  
기능을 새로 추가하는 단계보다는 실제 사용자 흐름에서 문제가 되는 부분을 찾아 정리하고 보완하는 데 집중했다.

## 진행 내용

- 전체 QA 결과 확인
- 오류 발생 기능과 재현 흐름 점검
- 미구현 또는 누락된 기능 확인
- 수정이 필요한 항목 우선순위 정리
- 가능한 범위의 fix 작업 진행
- 수정 후 기능 동작 재확인

## 정리한 부분

QA에서 나온 문제는 단순히 “에러가 난다”로 끝내지 않고, 어떤 사용자 흐름에서 발생했는지 확인하는 것이 중요했다.

예를 들어 다음 기준으로 확인했다.

- 특정 버튼 클릭 시 동작하지 않는지
- API 요청은 성공하지만 화면 반영이 안 되는지
- 인증이 필요한 요청에서 토큰 처리가 빠졌는지
- DB 데이터는 있는데 화면에서 표시되지 않는지
- 구현 자체가 누락된 기능인지
- 기존 기능 수정으로 다른 흐름에 영향이 생기는지

오류 수정은 기능 구현보다 범위 판단이 더 중요했다.  
당장 고칠 수 있는 항목과 추가 논의가 필요한 항목을 나누고, 전체 일정 안에서 처리 가능한 부분부터 반영했다.

## 느낀 점

전체 QA를 진행하면서 기능이 “구현됨”과 “사용자가 문제없이 사용할 수 있음”은 다르다는 점을 다시 확인했다.  
작은 오류나 누락도 실제 흐름에서는 사용성을 크게 떨어뜨릴 수 있기 때문에, QA 결과를 기준으로 하나씩 재현하고 수정하는 과정이 중요했다.

또한 수정 후에는 해당 기능만 보는 것이 아니라 연결된 흐름까지 다시 확인해야 한다.  
하나의 fix가 다른 기능에 영향을 줄 수 있기 때문에, QA는 단순 점검이 아니라 프로젝트 완성도를 높이는 과정이라고 느꼈다.
