# 취미 장비 대여 플랫폼 기획

# 서비스 정의

사용자가 취미 장비를 원하는 기간으로 예약하고, 장비 제공자가 예약 승인부터 대여·반납까지 관리하는 플랫폼.

> **MVP 검증 목표:** 같은 장비의 예약 기간이 겹치지 않도록 관리하면서 하나의 대여 거래를 끝까지 완료할 수 있는가?
> 

# MVP 사용자

모든 회원은 별도 전환이나 승인 없이 장비를 대여하고 본인의 장비를 제공할 수 있다. 제공자와 대여자는 계정 역할이 아니라 개별 거래에서 결정된다.

## 장비 대여 시

- 장비 목록·상세 조회
- 장비명 키워드 검색
- 대여 시작일·종료일 선택
- 예약 가능 여부와 결제 금액 확인
- 예약 신청
- 내 예약 조회
- 예약 대기 상태에서 취소
- 본인이 등록한 장비는 예약 불가

## 장비 제공 시

- 장비 등록·수정
- 일일 대여료와 보증금 설정
- 받은 예약 조회
- 예약 승인·거절
- 장비 수령 처리
- 장비 반납 처리

# 회원 정책

- 회원가입 정보는 닉네임·이메일·연락처·비밀번호다.
- 이메일로 로그인한다.
- 이메일과 닉네임은 중복을 허용하지 않는다.
- 이메일 인증과 본인인증은 MVP에서 제외한다.
- 비밀번호는 암호화해 저장한다.
- 장비 상세 화면에는 제공자 닉네임과 교환 역을 공개한다.
- 연락처는 예약 확정 전에는 공개하지 않고, 확정 후 예약 상세에서 거래 상대에게만 공개한다.
- 이메일은 예약 확정 후에도 거래 상대에게 공개하지 않는다.
- 모든 회원은 장비 대여와 제공 기능을 모두 사용할 수 있다.
- 닉네임은 중복 검사 후 변경할 수 있다.
- 연락처는 번호 변경 등을 고려해 수정할 수 있다.
- 계정 식별자인 이메일은 변경할 수 없다.
- 로그인 상태에서 현재 비밀번호 확인 후 새 비밀번호로 변경할 수 있다.
- 비밀번호 찾기·재설정 메일과 회원 탈퇴는 추가 확장 기능으로 둔다.

# 핵심 워크플로

1. 회원이 장비·교환 역·일일 대여료·보증금을 한 번에 등록한다.
2. 다른 회원이 대여 기간과 희망 수령·반납 시간을 선택한다.
3. 시스템이 유효한 예약 대기를 포함한 기존 예약과 기간이 겹치는지 검사한다.
4. 예약 가능하면 결제 금액을 계산하고 회원이 최종 예약을 신청한다.
5. 장비 제공자가 24시간 안에 예약을 승인하거나 거절한다.
6. 역에서 장비를 전달한 제공자가 **수령 확인 요청**으로 변경한다.
7. 대여자가 수령을 승인하면 **대여 중**으로 변경한다.
8. 대여자가 장비를 돌려준 뒤 **반납 중**으로 변경한다.
9. 제공자가 장비를 확인하고 **거래 완료**로 변경한다.

# 마이페이지 예약 목록

- 예약 목록은 **내가 빌린 예약**과 **내 장비에 들어온 예약**으로 구분한다.
- 각 목록은 **전체·처리 필요·진행 중·종료** 필터를 제공한다.
- 내가 빌린 예약의 처리 필요: 수령 확인 요청
- 내 장비에 들어온 예약의 처리 필요: 예약 대기·반납 중
- 진행 중: 예약 확정·수령 확인 요청·대여 중·반납 중
- 종료: 거래 완료·예약 취소·예약 거절·예약 만료·제공자 취소
- 기본 필터는 전체다.
- 마이페이지 메뉴에 처리 필요 예약 건수를 표시한다.
- 행동이 필요한 예약에는 **처리 필요** 배지를 표시한다.
- 별도 알림함과 이메일·문자·푸시 알림은 MVP에서 제공하지 않는다.
- 수령 확인 요청과 반납 중 상태는 상대방이 직접 확인할 때까지 유지한다.
- 시간이 지나도 자동으로 대여 중 또는 거래 완료로 변경하지 않는다.
- 미확인 예약은 마이페이지에 계속 처리 필요로 표시한다.
- 신고·분쟁·관리자 강제 상태 변경은 추가 확장 기능으로 둔다.

# 예약 상태

```bash
예약 대기 → 예약 확정 → 수령 확인 요청 → 대여 중 → 반납 중 → 거래 완료
          ↘ 예약 거절       ↘ 대여자 취소·제공자 취소

예약 대기 → 예약 취소
예약 대기 → 예약 만료
```

- 고객은 **예약 대기** 상태에서만 승인 없이 취소할 수 있다.
- 대여자와 제공자는 예약 확정 후에도 수령 확인 요청 전까지 예약을 취소할 수 있다.
- 수령 확인 요청 이후에는 양쪽 모두 취소할 수 없다.
- 대여자 취소 사유는 **일정 변경·제공자와 연락 불가·교환 장소·시간 문제·기타**로 제한한다.
- 제공자는 예약 대기 상태에서 승인 또는 거절할 수 있다.
- 예약 거절 시 **희망 시간 이용 어려움·해당 일정 대여 불가·장비 점검 필요·기타** 중 사유를 선택한다.
- 제공자 취소 사유는 **장비 고장·일정 불가·등록 정보 오류·기타**로 제한한다.
- 취소 수수료는 없으며 취소 즉시 해당 기간의 날짜 차단을 해제한다.
- 예약 대기·예약 확정·수령 확인 요청·대여 중·반납 중 상태는 해당 기간의 신규 예약을 차단한다.
- 예약 거절·예약 취소·예약 만료·제공자 취소·거래 완료 상태는 신규 예약을 차단하지 않는다.

# 동시 예약 정책

- 장비 상세 화면을 여러 사용자가 동시에 보고 날짜를 선택하는 것은 허용한다.
- 최종 예약 신청 API가 서버에서 먼저 성공한 사용자가 해당 기간을 선점한다.
- 서버는 예약 생성 직전에 기간 중복을 다시 검사한다.
- 먼저 처리된 예약이 있으면 뒤 요청은 실패 처리하고 **이미 예약된 기간입니다**라고 안내한다.
- 화면에서 확인한 예약 가능 여부는 최종 예약 성공을 보장하지 않는다.

> 구현 시 장비 행을 잠근 트랜잭션 안에서 중복 검사와 예약 생성을 함께 처리한다.
> 

# 예약 대기 만료 정책

- 예약 대기는 신청 시점부터 24시간 동안만 유효하다.
- 24시간 안에 제공자가 승인하거나 거절하지 않으면 **예약 만료** 처리한다.
- 만료된 예약은 해당 기간의 신규 예약을 차단하지 않는다.
- 고객과 제공자는 만료된 예약 내역을 조회할 수 있다.

# 대여 기간 및 교환 정책

- 요금은 날짜 단위로 계산하며 시간 단위 대여는 지원하지 않는다.
- 시작일과 종료일을 모두 지정하고 대여 일수에 포함한다.
- 당일 대여는 1일이다.
- 시작일은 종료일보다 늦을 수 없고 과거 날짜로 예약할 수 없다.
- 같은 장비는 종료일 당일에 다른 고객에게 다시 대여할 수 없다. 다음 예약은 종료일 다음 날부터 가능하다.
- 장비 등록 시 정확한 주소 대신 교환할 역 하나를 지정한다. 예: 정발산역.
- 고객은 예약 신청 시 희망 수령 시간과 반납 시간을 입력한다.
- 예약 비고는 선택 항목이며 200자 이내로 입력한다.
- 시간은 00:00부터 23:30까지 30분 단위로 선택한다.
- 제공자는 제시된 역·시간을 확인한 뒤 예약 전체를 승인하거나 거절한다.
- 제공자가 **시간 협의 필요**로 거절하면 해당 예약은 종료되고 날짜 차단이 해제된다.
- 고객은 새로운 시간을 선택해 다시 예약을 신청할 수 있다.
- 채팅과 예약 내용 수정 기능은 MVP에서 지원하지 않는다.

# 금액 및 현장 정산 정책

```
대여 일수 = 종료일 - 시작일 + 1
대여료 = 일일 대여료 × 대여 일수
결제 금액 = 대여료 + 보증금
```

- 일일 대여료와 보증금은 제공자가 장비 등록 시 함께 입력한다.
- 화면과 문서에서 명칭은 **결제 금액**으로 통일한다.
- 결제 금액은 안내용이며 실제 정산은 역에서 만난 거래 당사자가 직접 진행한다.
- 현금·계좌이체 등 정산 수단은 당사자가 결정한다.
- 플랫폼은 계좌번호·입금 여부·보증금 반환 여부를 저장하거나 보증하지 않는다.
- 예약 당시 일일 대여료와 보증금을 예약 데이터에 저장한다.
- 이후 장비 가격이 변경돼도 기존 예약 금액은 변경하지 않는다.
- PG 결제·에스크로·보증금 자동 반환은 추가 확장 기능으로 둔다.

# 장비 검색·정렬 정책

- 검색어는 장비명과 제조사에 함께 적용한다.
- 카테고리는 전체 또는 하나만 선택할 수 있다.
- 정렬은 **최신 등록순·낮은 대여료순·높은 대여료순**을 제공한다.
- 기본 정렬은 최신 등록순이다.
- 가격 정렬은 보증금을 제외한 일일 대여료를 기준으로 한다.
- 대여 많은 순은 추가 확장 기능으로 둔다.
- 대여 중지된 장비는 목록과 검색 결과에서 제외한다.
- 예약이 있는 장비는 목록에 계속 표시한다.
- 장비 상세 달력에서 예약 대기·예약 확정·수령 확인 요청·대여 중·반납 중인 날짜를 비활성화한다.
- 일부 날짜가 예약됐더라도 사용자는 남은 날짜를 선택해 예약할 수 있다.

# 장비 등록 정책

장비 등록 항목은 다음과 같다.

- 장비명: 자유 입력
- 카테고리: **카메라·촬영, 악기, 캠핑, 스포츠·레저, 의류·소품, 게임·전자기기, 공구, 기타** 중 선택
- 제조사: 선택 입력, 자유 입력. 값이 없으면 상세 화면의 제조사 항목은 유지하고 값을 비워 표시
- 구성품 및 상태: 300자 이내 자유 입력
- 교환 역: 역명으로 검색해 미리 등록된 국내 역 목록에서 하나 선택
- 일일 대여료: 제공자 직접 입력
- 보증금: 제공자 직접 입력
- 대표 사진: JPG·PNG 형식의 5MB 이하 파일 1장

역 검색은 역명만 기준으로 하며 검색 결과에는 구분을 위해 역명과 노선명을 표시한다. 지역명은 검색과 화면 표시에 사용하지 않는다.

# 장비 및 예약 정보 보존 정책

- MVP에서는 장비 게시물 1개를 실물 장비 1개로 취급한다.
- 수량·재고 계산은 하지 않는다.
- 예약 신청 시 장비명·카테고리·제조사·구성품 및 상태·대표 사진·교환 역·희망 수령·반납 시간·비고·일일 대여료·보증금을 예약 정보에 복사해 저장한다.
- 예약 상세 화면에는 현재 장비 게시물이 아닌 예약 당시 저장한 정보를 표시한다.
- 예약 이력이 없는 장비는 모든 항목을 수정하거나 삭제할 수 있다.
- 예약 이력이 생기면 장비명·카테고리·제조사는 수정할 수 없다.
- 다른 제품으로 바꾸려면 기존 장비를 대여 중지하고 새 장비로 등록한다.
- 예약 이력이 있는 장비도 설명·추가 사진·가격·보증금은 수정할 수 있지만 기존 예약에는 반영되지 않는다.
- 예약 대기·예약 확정·수령 확인 요청·대여 중·반납 중 상태에서는 예약 기간·예약 장비·구성품·교환 역·수령·반납 시간·비고·결제 금액을 변경할 수 없다.
- 예약 이력이 있는 장비는 삭제하지 않고 **대여 중지** 처리한다.
- 대여 중지된 장비는 신규 예약할 수 없다.
- 제공자는 본인이 등록한 장비를 예약할 수 없다.

# 구현 기능 우선순위

## P0 — 반드시 구현

- 닉네임·이메일·연락처·비밀번호 회원가입
- 이메일·비밀번호 로그인
- 이메일·닉네임 중복 검사
- 닉네임·연락처·비밀번호 수정
- 모든 회원의 장비 대여·제공
- 장비 등록·수정·대여 중지·조건부 삭제
- 장비 등록 폼에서 카테고리·장비명·제조사·구성품 및 상태 입력
- 국내 역 초기 데이터와 교환 역 선택
- 장비 등록 폼에서 일일 대여료·보증금 입력
- 장비 대표 사진 1장 업로드
- JPG·PNG 형식과 5MB 이하 파일 검증
- 대여 중지 장비를 제외한 장비 목록·상세

# 로컬 개발 환경 확정

- 배포는 보류하고 React와 Spring Boot를 로컬에서 실행한다.
- 장비 이미지는 Spring Boot 실행 경로의 `./uploads/equipment` 폴더에 저장한다.
- DB에는 이미지 파일이 아니라 `/files/equipment/{파일명}` 형태의 접근 경로만 저장한다.
- 서버 시간·예약 시간·화면 표시는 모두 Asia/Seoul 한국 시간으로 통일한다.
- 예약 대기는 expiresAt 도달 시 만료 대상이 되며 서버가 매분 만료 작업을 실행한다.
- 승인 API는 스케줄 처리 여부와 관계없이 expiresAt을 다시 검사해 만료 시각 이후 승인을 차단한다.
- 서비스 이용약관과 개인정보 수집 동의 시각을 회원 데이터에 저장한다.
- 역 초기 데이터는 첨부한 전체 도시철도노선정보 파일에서 수도권 노선만 추출한다.
- 배포·S3·PG 연동은 추가 확장으로 둔다.

# MVP 완료 기준

1. 회원 A가 카메라 장비를 등록한다.
2. 고객 A와 고객 B가 같은 기간을 선택한다.
3. 고객 A의 최종 예약 신청이 먼저 처리돼 예약 대기가 생성된다.
4. 고객 B의 신청은 기간 중복으로 실패한다.
5. 제공자가 고객 A의 예약을 승인한다.
6. 제공자가 장비 전달 후 수령 확인을 요청한다.
7. 고객 A가 수령을 승인해 대여 중으로 변경한다.
8. 고객 A가 반납 중으로 변경한다.
9. 제공자가 장비를 확인하고 거래 완료로 변경한다.
10. 거래 완료 후 해당 기간이 다시 예약 가능 상태로 조회된다.
