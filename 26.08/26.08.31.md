# 문서 목적

MVP 정책과 화면 정의를 실제 데이터 구조와 관계로 변환한다.

- MVP 정책 기획서
- MVP 화면 정의서
- API 명세서

# 설계 원칙

- MySQL 기준
- MVP에 필요한 테이블만 구성
- 모든 회원은 장비 대여와 제공 가능
- 장비 게시물 하나는 실물 장비 하나
- 예약 생성 시 장비·교환 역·가격 정보를 스냅샷으로 저장
- 예약 상태 변경과 기간 중복을 서버에서 검증
- enum 값은 DB에는 VARCHAR로 저장하고 Java enum으로 관리
- 금액은 소수점 없는 원 단위 BIGINT로 저장
- 서버·DB·API의 업무 시간 기준은 Asia/Seoul로 통일

# 엔티티

- User
- Station
- Equipment
- Reservation

별도의 회원 역할·카테고리·이미지·예약 이력·취소 사유 테이블은 MVP에서 만들지 않는다.

# 테이블 정의

## users

| 컬럼 | 자료형 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| id | BIGINT | O | PK, AUTO_INCREMENT |
| email | VARCHAR(255) | O | UNIQUE, 로그인 ID, 변경 불가 |
| password_hash | VARCHAR(255) | O | 암호화된 비밀번호 |
| nickname | VARCHAR(20) | O | UNIQUE |
| phone | VARCHAR(20) | O | 변경 가능 |
| terms_agreed_at | DATETIME | O | 서비스 이용약관 동의 시각 |
| privacy_agreed_at | DATETIME | O | 개인정보 수집·이용 동의 시각 |
| created_at | DATETIME | O | 생성 시각 |
| updated_at | DATETIME | O | 수정 시각 |

회원 탈퇴와 역할 구분을 MVP에서 제외하므로 status·role·deleted_at 컬럼은 두지 않는다.

## stations

| 컬럼 | 자료형 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| id | BIGINT | O | PK, AUTO_INCREMENT |
| name | VARCHAR(50) | O | 역명 |
| line | VARCHAR(50) | O | 노선명 |

역 검색은 name을 기준으로 하며 결과에는 name과 line을 표시한다.

초기 데이터는 첨부한 **전체_도시철도노선정보_20260630.xlsx**의 정거장구성 값을 파싱해 수도권 노선만 적재한다. 코드와 역명이 한 셀에 묶여 있으므로 역 단위 행으로 변환하고 동일 역·노선 중복을 제거한다.

장비 카테고리:

```
CAMERA
MUSICAL_INSTRUMENT
CAMPING
SPORTS_LEISURE
CLOTHING_PROPS
GAME_ELECTRONICS
TOOLS
ETC
```

장비 상태:

```

```

예약 이력이 없는 장비는 실제 삭제하고, 예약 이력이 있으면 PAUSED만 허용한다.

## reservations

| 컬럼 | 자료형 | 필수 | 제약·설명 |
| --- | --- | --- | --- |
| id | BIGINT | O | PK, AUTO_INCREMENT |
| equipment_id | BIGINT | O | FK → equipment.id |
| renter_id | BIGINT | O | FK → users.id |
| status | VARCHAR(30) | O | ReservationStatus |
| start_date | DATE | O | 대여 시작일 |
| end_date | DATE | O | 대여 종료일 |
| pickup_time | TIME | O | 수령 시간, 30분 단위 |
| return_time | TIME | O | 반납 시간, 30분 단위 |
| note | VARCHAR(200) | X | 예약 비고 |
| expires_at | DATETIME | O | 예약 대기 만료 시각 |
| reason_code | VARCHAR(50) | X | 거절·취소 사유 |
| canceled_by | BIGINT | X | FK → users.id, 취소한 회원 |
| snapshot_name | VARCHAR(50) | O | 예약 당시 장비명 |
| snapshot_category | VARCHAR(30) | O | 예약 당시 카테고리 |
| snapshot_manufacturer | VARCHAR(30) | X | 예약 당시 제조사 |
| snapshot_description | VARCHAR(300) | O | 예약 당시 구성품·상태 |
| snapshot_image_url | VARCHAR(500) | O | 예약 당시 대표 사진 |
| snapshot_station_name | VARCHAR(50) | O | 예약 당시 교환 역 |
| snapshot_station_line | VARCHAR(50) | O | 예약 당시 노선 |
| snapshot_daily_rate | BIGINT | O | 예약 당시 일일 대여료 |
| snapshot_deposit | BIGINT | O | 예약 당시 보증금 |
| rental_fee | BIGINT | O | 대여료 합계 |
| total_amount | BIGINT | O | 대여료 + 보증금 |
| created_at | DATETIME | O | 예약 신청 시각 |
| updated_at | DATETIME | O | 상태 변경 시각 |

reservation_time은 별도로 두지 않고 created_at을 예약 신청 시각으로 사용한다.

제공자는 reservations에 중복 저장하지 않고 다음 관계로 조회한다.

```
reservations.equipment_id
→ equipment.owner_id
→ users.id
```

# 관계

```
users 1 ── N equipment
users 1 ── N reservations (renter_id)
users 1 ── N reservations (canceled_by)
stations 1 ── N equipment
equipment 1 ── N reservations
```

- 한 회원은 여러 장비를 등록할 수 있다.
- 한 회원은 여러 예약을 신청할 수 있다.
- 한 역은 여러 장비의 교환 역이 될 수 있다.
- 한 장비는 기간이 겹치지 않는 여러 예약 이력을 가질 수 있다.
- 장비 소유자와 예약자는 같을 수 없다.

# 예약 상태

```
PENDING
CONFIRMED
RECEIPT_REQUESTED
RENTING
RETURNING
COMPLETED
REJECTED
CANCELED
EXPIRED
```

대여자 취소와 제공자 취소는 별도 상태로 나누지 않는다.

```
status = CANCELED
canceled_by = 취소한 회원 ID
reason_code = 취소 사유
```

# 금액 계산

```
rental_days = end_date - start_date + 1
rental_fee = snapshot_daily_rate × rental_days
total_amount = rental_fee + snapshot_deposit
```

계산에 사용한 단가와 계산 결과를 모두 저장해 장비 가격 변경의 영향을 받지 않도록 한다.

# 주요 제약조건

## 사용자

- users.email UNIQUE
- users.nickname UNIQUE
- 비밀번호 평문 저장 금지

## 장비

- equipment.owner_id와 예약의 renter_id가 같으면 예약 불가
- daily_rate > 0
- deposit >= 0
- status가 ACTIVE인 장비만 신규 예약 가능
- 예약 이력이 있는 장비는 삭제 불가

## 예약

- start_date <= end_date
- 과거 날짜 예약 불가
- pickup_time과 return_time은 00분 또는 30분
- PENDING 상태에서 expires_at 이후 승인 불가
- 예약 당시 스냅샷과 금액은 생성 후 수정 불가
- 예약 대기·확정·수령 확인 요청·대여 중·반납 중 기간은 서로 겹칠 수 없음

기간 중복 조건:

```
existing.start_date <= requested.end_date
AND existing.end_date >= requested.start_date
```

예약을 차단하는 상태:

```
PENDING
CONFIRMED
RECEIPT_REQUESTED
RENTING
RETURNING
```

예약 생성 시 equipment 행을 잠근 트랜잭션 안에서 중복 조회와 INSERT를 함께 처리한다.

# 인덱스

```
UNIQUE users(email)
UNIQUE users(nickname)

INDEX stations(name)

INDEX equipment(owner_id)
INDEX equipment(status, category, created_at)
INDEX equipment(daily_rate)

INDEX reservations(renter_id, created_at)
INDEX reservations(equipment_id, status, start_date, end_date)
INDEX reservations(status, expires_at)
```

# ERD 요약

```
users
  ├─< equipment >─ stations
  └─< reservations >─ equipment

reservations.canceled_by ─> users.id
```
